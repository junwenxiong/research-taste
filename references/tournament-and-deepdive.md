# 多模型真盲评、资源落地深挖与交付契约

## 1. L2｜脱敏候选卡片固定格式（防字数与风格偏见）

将幸存/融合候选统一编号 `A, B, C...`，**彻底删除作者名、模型名、流派名、比喻与自夸词**，每卡严格控制 10–14 行等长结构：

```markdown
## Candidate X｜<中性精准题名>
- **核心问题（零黑话、零比喻）**：<直白说明输入、现有失败根因与目标改动>
- **核心机制与删减**：<1 个清晰抽象或数学定义，明确说明删掉了哪些复杂模块>
- **实时核验近邻与精确 Delta**：<列出近 1–3 年最强真实论文及经典先例 + 剩余唯一不可替代增量>
- **10× 缩放检验与最大风险**：<基础模型强 10× 后增值还是作废？最可能翻车的硬伤在哪？>
- **1 周验证与保守下界**：<低成本验证对照（含 1 条故意保守常规下界）、量化通过线与硬止损线>
```

## 2. L2｜统一裁判 Prompt 四要素（机解析契约）

在 `JUDGE_PROMPT.md` 中强制所有裁判仅依据候选文本独立输出 4 个部分，禁止调用任何外部文件读取工具：
1. **7 维独立打分表（1–10 分，满分 70，强制拉开分差）**：列顺序固定为 `ID | Impact | Novelty | BitterLesson | Simplicity | Feasibility/Physics | Leverage | Taste | Total | 短评`（≤30 字指出核心死穴），并在表后逐题补写 1–2 句关键硬伤。
2. **完整 $\binom{n}{2}$ 场配对 CSV 代码块**（平局 `TIE` 不超过总场次 10%，`REASON` 禁止英文逗号）：
   ```csv
   PAIR,LEFT,RIGHT,WINNER,REASON
   1,A,B,LEFT,一句话核心胜出理由
   ```
3. **Top 3 推荐（各附 1 个最怕翻车点）+ 2 个必须硬砍题（各附致命死因）**。
4. **1–2 条 Meta-Review 抽象升维提案**：写清“删掉了什么、留下的唯一原语是什么、第一个否证实验是什么”（严禁把两题简单拼成 `A+B`）。

## 3. 物理隔离执行命令（零互相偷看）

先拼接 `BLIND_INPUT.txt = JUDGE_PROMPT.md + "\n\n---\n\n" + CANDIDATES_BLIND.md`。**必须先落盘锁定当前主控模型自己的裁判报告（如 `JUDGE_MODEL1.md`），再并行启动其他异构模型**（模型名从团队或工作区统一配置读取，不写死版本号）：

- **Claude Code 隔离运行**（`--tools ""` 禁用一切工具，纯 stdin→stdout）：
  ```bash
  claude --bare -p "严格按输入指令直接输出完整报告，不要调用任何工具。" \
    --model "${CLAUDE_MODEL:-opus}" --effort high --tools "" \
    < BLIND_INPUT.txt > JUDGE_CLAUDE.md
  ```
- **Codex 隔离运行**（`-s read-only -C /tmp --ephemeral` 隔离于 `/tmp`，无法接触工作目录其他裁判文件）：
  ```bash
  codex exec -m "${CODEX_MODEL:?set CODEX_MODEL}" -c model_reasoning_effort="high" \
    -s read-only -C /tmp --skip-git-repo-check --ephemeral \
    -o JUDGE_CODEX.md - < BLIND_INPUT.txt
  ```
- **汇总与偏见/自洽性审计**：
  ```bash
  python3 scripts/aggregate_elo.py \
    --judges Gemini=JUDGE_GEMINI.md Claude=JUDGE_CLAUDE.md Codex=JUDGE_CODEX.md \
    --cands A,B,C,D,E \
    --provenance provenance.json \
    --out TOURNAMENT_SUMMARY.md
  ```

## 4. L3｜资源落地两轮跨模型深挖协议

对终选 Top 1–2 课题，按以下固定 Brief 结构组织两轮协作：

### 第 1 轮（独立推演 + 二次精准查重）
向各模型提供统一 `BRIEF_DEEPDIVE.md`，包含：
1. **写作硬约束**：严禁比喻与造词；面向 CS/AI 读者直白写清输入、模型结构、输出动作、数学定义、失败根因与对照；未测数字一律明示为“预注册判断线”。
2. **团队真实资源清单**：现有算力/显存、硬件/仿真器、现役系统层级与不可突破约束（明确不从零训超大模型等红线）。
3. **必须正面回答的 5 个问题**：
   - Q1：技术载体对比（如前沿黑盒 API + 确定性底层 vs + 轻量本地模块 vs 端到端重训）及顶会防拒稿方案；
   - Q2：基础模型“该做什么 / 严禁做什么”职责边界表；
   - Q3：针对具体算法与载体的**二次精准查重**（经典先例 + 近两周预印本）及重构后的 1–2 项不可替代增量；
   - Q4：完整算法闭环、反泄露/防作弊实验协议、保守强组合下界与 **D1–D3 前置生死闸门**（先测增益上限，不过即停）；
   - Q5：团队条件下最可能翻车的 2 个具体瓶颈及提前预警指标。

### 第 2 轮（针对硬分歧正面交叉质询）
汇总第 1 轮三份报告，提炼 **3–5 个关键分歧点**（例如：新颖性是否站得住、前置闸门怎么测、多方向如何排期防互拖），去掉客套话发给各模型做针对性质询，最终收敛为唯一执行定案。

## 5. 双层表达与配图质检契约

1. **终选方案文档强制结构**：
   - **第 0 节（剥离外壳，纯字面直白）**：不出现公式、不展开文献综述、不堆审稿防御；用 2–3 段话 + 1 个具体场景例子讲透“系统看到什么 → 为什么现有方法做不好 → 我们改了哪一步 → 这篇工作核心要证明什么”。
   - **第 1–4 节（学术严谨与工程执行）**：强近邻划界 → 完整算法与输入输出 → 防作弊协议与保守下界 → D1–D3 生死闸门与 D1–D7 预注册实验。
2. **科学原理图独立视觉质检清单**（若文档含生成图表，须由独立视觉检查核对）：
   - 无中文/数学符号缺字（无方块 tofu，无未解析 LaTeX `$` 或 `\t` 转义错）；
   - 无文字与框线/箭头/坐标轴重叠或被边界裁切；
   - 无多余生活比喻标签或重复语义标签。
